# Denial Root-Cause Analysis

## Objective

The purpose of this analysis is to identify recurring denial patterns and determine the underlying process issues contributing to revenue loss and AR growth.

All data in this analysis is fictional.

---

## Denial Categories

| Denial Category | Example Root Cause | Corrective Action | Preventive Action |
|---|---|---|---|
| Eligibility | Coverage not verified | Verify coverage and correct claim | Pre-service eligibility checklist |
| Authorization | Authorization missing | Obtain/review authorization | Authorization verification before service |
| Coding | Incorrect code/modifier | Review and correct claim | Coding quality review |
| Timely Filing | Submission delay | Submit appeal with supporting information | Monitor filing deadlines |
| Duplicate | Duplicate submission | Contact payer/correct claim | Duplicate claim validation |
| Provider | Enrollment issue | Verify provider enrollment | Credentialing status monitoring |
| COB | Other insurance information outdated | Update COB information | Periodic insurance verification |
| Medical Necessity | Documentation insufficient | Review documentation and appeal | Pre-billing documentation review |
| Patient Information | Member information mismatch | Correct demographics/insurance | Front-end data validation |
| Documentation | Required records missing | Obtain documentation | Documentation checklist |

---

# Root-Cause Analysis Method

## Step 1 – Identify the Pattern

Review denial data by:

- Payer
- Denial category
- Dollar value
- Department
- Provider
- Date of service
- Frequency

## Step 2 – Identify the Process Failure

Ask:

- Where did the error occur?
- Was the information available?
- Was the information verified?
- Was the claim reviewed before submission?
- Was the payer requirement understood?
- Was the process followed correctly?

## Step 3 – Determine Corrective Action

The corrective action should address the individual denied claim.

## Step 4 – Determine Preventive Action

The preventive action should address the underlying process so similar denials are less likely to occur.

# Example Analysis

## Eligibility Denials

### Problem

Multiple claims were denied because coverage was inactive on the date of service.

### Root Cause

Eligibility verification was not consistently completed or updated before claim submission.

### Corrective Action

Review the affected accounts and verify coverage information.

### Preventive Action

Implement a standardized eligibility verification checklist and document verification before services are billed.

### KPI to Monitor

- Eligibility denial rate
- Eligibility verification rate
- Claim rejection rate

---

# Authorization Denials

### Problem

Claims were denied because required authorization information was missing.

### Root Cause

Authorization requirements were not consistently identified before services were provided or billed.

### Corrective Action

Review authorization records and submit appropriate corrected claims or appeals.

### Preventive Action

Add an authorization verification checkpoint to the pre-service workflow.

### KPI to Monitor

- Authorization denial rate
- Authorization verification rate
- Appeal success rate

---

# Coding Denials

### Problem

Claims were denied because of coding-related issues.

### Root Cause

Incorrect coding, modifier selection, or claim configuration.

### Corrective Action

Review the claim and coding information and submit a corrected claim when appropriate.

### Preventive Action

Implement coding quality checks and monitor recurring coding denial patterns.

### KPI to Monitor

- Coding denial rate
- First-pass claim acceptance rate
- Corrected claim rate

---

# Timely Filing Denials

### Problem

Claims were denied because they were submitted after the payer's filing deadline.

### Root Cause

Delay between service, charge entry, claim preparation, and submission.

### Corrective Action

Review submission history and available filing documentation and pursue appropriate payer action.

### Preventive Action

Monitor claim submission aging and establish escalation rules for approaching filing deadlines.

### KPI to Monitor

- Timely filing denial rate
- Average claim submission turnaround
- Claims pending submission

# Recommended Denial Dashboard

The following KPIs can be used in an RCM denial dashboard:

| KPI | Purpose |
|---|---|
| Total Denials | Measure overall denial volume |
| Denied Amount | Measure financial impact |
| Denial Rate | Measure percentage of claims denied |
| Top Denial Category | Identify major problem areas |
| Top Payer | Identify payer-specific trends |
| Appeal Success Rate | Measure recovery effectiveness |
| Average Resolution Days | Measure operational efficiency |
| Recovery Rate | Measure recovered revenue |
| Repeat Denial Rate | Identify recurring process failures |

# Final Analysis

Denial management should not focus only on resolving individual claims.

A strong RCM denial management process should:

1. Identify the denial.
2. Determine the financial impact.
3. Identify the root cause.
4. Take corrective action.
5. Recover appropriate reimbursement.
6. Identify recurring patterns.
7. Implement preventive action.
8. Monitor KPIs.
9. Continuously improve the billing process.
